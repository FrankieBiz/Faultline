## 1. Fix now

Critical and high-severity defects, all confirmed.

### 1. **The crawler's commit-action guard is a label denylist, so it still submits real forms on external sites**
- **Location:** `tools/browser-runner/src/crawler.ts:246` (the `COMMIT` regex), header claim at `crawler.ts:9-12`
- **Raised by:** contrarian (safety, high), bug-hunter (safety, high). Two personas found this independently.
- **Evidence:** With origin `https://shop.example.com`, `scoreClickable` gives a positive score to "Place your order", "Order now", "Book now", "Donate", "Subscribe", "Reserve", "Transfer funds", "Publish", "Post comment" and "Checkout with PayPal". Only "Pay", "Confirm" and "Place order" are refused. bug-hunter's host-resolver repro sent three real POSTs (`/comments` with crawler-filled text, `/orders`, `/donate`) to an external origin, and the crawl still ended `status=clean stop=exhausted`. A bare `<input type=submit>` has an empty name, so `COMMIT` never matches it.
- **Recommendation:** On non-local origins, switch to an allowlist. Never click a submit control (`type=submit`, or a button inside a `method=post` form) and never fill textareas in POST forms unless `allowCommitActions` is set. As a minimum stopgap, widen the regex (`place (your )?order`, `order now`, `book`, `reserve`, `donate`, `subscribe`, `transfer`, `publish`, `post`). Add these labels and the shop.example.com repro as regression tests, and soften the "cannot place an order" header so it matches what the guard actually enforces.
- **Effort:** S for the regex stopgap, M for the submit-control allowlist.
- **Verdict:** Confirmed by both verifiers, each running `dist/crawler.js`. The exact scores differ from contrarian's figures, but every label listed scores above zero, which means the crawler clicks it.

### 2. **The gate returns SAFE_TO_DEPLOY on hosted preview URLs without ever pressing checkout**
- **Location:** `tools/browser-runner/src/crawler.ts:322` (and `:849`), `services/repair-orchestrator/app/cli_crawl.py:600`, `docs/PREFLIGHT_GATE.md:166-175`
- **Raised by:** contrarian (overclaim, high).
- **Evidence:** On a non-local origin, commit-named controls are dropped from `ranked` and nothing is recorded, so the crawl ends with `stop_reason: "exhausted"` and `gate_result` passes it with exit 0. The docs and the faultline-gate skill tell users to gate `$PREVIEW_URL`. The Python gate, scan and crawl commands have no `--allow-commit-actions` option, and the CI self-test only targets 127.0.0.1. The headline bug (an HTTP 500 on Place order) therefore cannot be found on a hosted preview, and the gate still reports a pass.
- **Recommendation:** Count the suppressed commit controls (`commit_controls_skipped`) in telemetry. If the count is above zero and commit actions were not allowed, end the crawl with a new stop_reason that the gate treats as `incomplete_crawl` (exit 1). Expose `--allow-commit-actions` on gate, scan and crawl. Add a non-local skipped-commit case to the gate self-test, and list this limit under "What it does not claim" in PREFLIGHT_GATE.md.
- **Effort:** M
- **Verdict:** Confirmed

### 3. **Hitting the 30-screen frontier cap is reported as "exhausted", so the gate passes with known pages unvisited**
- **Location:** `tools/browser-runner/src/crawler.ts:1029`; the pass check is at `cli_crawl.py:600` and in `agent-gate.ts:110` (`crawlCompleted`)
- **Raised by:** bug-hunter (bug, high).
- **Evidence:** In the repro, `/catalog` links to `/p/1` through `/p/40`, and `/p/35` throws. The run printed `status=clean stop=exhausted actions=2 screens=30 visited_p35=false`. - **Recommendation:** When the cap blocks a remaining frontier entry, end with a distinct `screen_limit` stop_reason. Make it a non-passing result in both the Python and TypeScript gates, and add the catalog repro as a test.
- **Effort:** S
- **Verdict:** Confirmed (repro reran)
