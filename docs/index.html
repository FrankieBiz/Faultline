A browser finds the checkout failure. A Meta model proposes a patch. Independent checks decide whether it works.

When an AI writes a hotfix, the error going away is not the same as the fix being right. FaultLine reproduces a real checkout crash in Chromium, asks Meta's muse-spark-1.3 for a one-file patch, and accepts it only after it passes a browser journey and 27 business checks inside an isolated, resource-limited runtime. Every number below comes from a recorded run, linked to its raw evidence.

What has to be true before a patch counts

Each gate can stop the job. A rejected first attempt sends its findings back to the model once.

  1. ReproduceA fresh Chromium session hits the failure, and the HTTP 500 is matched to the server's own error log.
  2. Ask for a bounded patchThe model returns a schema-checked, single-file unified diff. The prompt states the business contract, not the bug.
  3. Check the patch itselfStale source hashes, wrong paths, oversized or malformed diffs, syntax errors, forbidden imports, and catch-all exception handlers are rejected.
  4. Build from a pinned commitThe diff is applied to a fresh worktree of the pinned fixture. Tests and reference answers are kept out of the candidate.
  5. Run it in isolationBubblewrap namespaces with no network, plus a cgroup v2 scope whose memory, task, and CPU limits are read back from the kernel.
  6. Verify behaviorThe same browser journey, then 27 HTTP checks for coupons, pricing, validation, and storage, all written from the contract.
  7. Keep the evidence, clean upScreenshots, traces, logs, and reports are hashed into a bundle. A cleanup failure blocks new jobs.

Run it yourself

You need

  • Linux with unprivileged user namespaces and Bubblewrap (bwrap)
  • cgroup v2 with a systemd user session (a desktop terminal, not a bare SSH login)
  • Git, Python 3.13 via uv, and Node.js 24 or later

What you will see

  • The Inspector at 127.0.0.1:4000; choose Run the demo
  • Without a Meta key the run uses deterministic-checkout-v1, labeled as such. It is not a Meta trial.
  • With META_API_KEY in an ignored .env, the same flow calls muse-spark-1.3
git clone https://github.com/FrankieBiz/Faultline.git
cd Faultline
make setup
make check
./scripts/start-demo.sh
./scripts/rehearse-demo.sh   # end-to-end job; exits non-zero unless verified and cleaned up
./scripts/demo-chaos.sh      # terminal walkthrough: containment probe and rejected wrong patches

Ports 3000, 4000, 8000, or 9000 already taken? The launcher reports occupied ports instead of killing their owners. Pick other ports, and point the rehearsal at the matching Inspector:

BUGGYSHOP_API_PORT=8400 FAULTLINE_PORT=9400 BUGGYSHOP_PORT=3400 INSPECTOR_PORT=4400 ./scripts/start-demo.sh
FAULTLINE_INSPECTOR_URL=http://127.0.0.1:4400 ./scripts/rehearse-demo.sh

What this does not claim

  • One registered live defect in one fixture store, plus an authored corpus of ten defects and eleven patches for the same route.
  • A verified result is a candidate with evidence. Nothing is deployed, merged, or routed to production traffic.
  • Namespaces and cgroup limits on a shared kernel, not a VM, and no seccomp filter. Passing the suite is evidence for the tested behavior, not proof that arbitrary code is safe.
  • One retained Meta repair and one Meta retry are recorded; repeated Meta trials and a Meta corpus run are still outstanding.
  • The replay's two Playwright trace archives include file paths from the build workstation.
