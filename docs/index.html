FaultLine is a controlled source-repair prototype targeting silent e-commerce checkout crashes. When customers buy without a coupon, the server crashes with an HTTP 500 error. FaultLine reproduces the incident in headless Chromium, prompts Meta's Model API under strict AST constraints, and verifies the repair candidate inside isolated Linux namespaces and kernel cgroup limits before issuing a verifiable result.

Why a 201 Symptom Check Fails

Traditional CI checks and naive LLM evaluators only verify: "Did the request return HTTP 201?"
On our evaluated holdout corpus, a symptom check accepted 5 out of 6 wrong patches. FaultLine accepted none of the wrong patches and only accepted the verified correct fix.
