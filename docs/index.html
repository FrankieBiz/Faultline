      What has to be true before a patch counts

      Any step can stop the job. A rejected first attempt sends its findings back to the model once.

      1. ReproduceA fresh Chromium session hits the failure, matched to the server’s own error log.
      2. Bounded patchOne schema-checked, single-file diff, written from the contract, not the bug.
      3. Patch policyStale hashes, wrong paths, oversized diffs, forbidden imports and catch-alls are rejected.
      4. Pinned buildApplied to a fresh worktree of the pinned fixture; tests stay out of the candidate.
      5. IsolationBubblewrap namespaces, no network, cgroup v2 limits read back from the kernel.
      6. VerifyThe same browser journey, then 27 HTTP business checks written from the contract.
      7. Evidence, cleanupArtifacts are checksummed; a cleanup failure blocks new jobs.

      Deploy gate: exit 1 blocks the pipeline

        Run it yourself

        Five commands on Linux bring up the store, the controller and the Inspector at 127.0.0.1:4000. Choose Run sandbox repair there.

        git clone https://github.com/FrankieBiz/Faultline.git
cd Faultline
make setup
make check
./scripts/start-demo.sh

        You need Linux with unprivileged user namespaces and Bubblewrap, cgroup v2 with a systemd user session, Git, Python 3.13 via uv, and Node.js 24 or later.

        Without a Meta key the run uses deterministic-checkout-v1 and is labeled as such; it is not a Meta trial. With META_API_KEY in an ignored .env, the same flow calls muse-spark-1.3.

        What this does not claim

        • One route. One registered defect in one fixture store, plus an authored corpus of ten defects and eleven patches for the same checkout. It is not a benchmark of arbitrary applications.
        • FaultLine never deploys. A verified result is a candidate with evidence; nothing is merged or routed to traffic. Apply writes only to the bundled demo store, and the gate’s exit 1 blocks a pipeline rather than shipping anything.
        • Single-file diffs. The crawler is deterministic heuristics, not a model, and a clean gate covers only the flows it reached after exploration finished.
        • A shared kernel. Bubblewrap namespaces and cgroup v2 limits, not a VM, with no seccomp filter and no external review. The sandbox confines; the authored checks judge.
        • Meta on one scenario. 3 of 3 trials and two retained replays on the seeded checkout. Not yet run on the ten-defect corpus, which only DeepSeek and the deterministic fallback have run. No recorded behavioral rejection followed by a Meta retry, and no Llama run.
        • Live runs are paused. The live service needs an isolated host and is off, so this page plays the recording instead. Not yet shown: user interviews or production use.
